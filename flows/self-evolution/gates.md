# 自进化流程卡点

本流程同时使用确定性检查和人工审批。确定性检查只判定可程序验证的条件；是否值得沉淀、分类是否正确、内容是否准确由人判断。

## 确定性检查

| 卡点 | 位置 | 检查内容 | 失败处理 |
|---|---|---|---|
| 入队预过滤 | `distill-enqueue.sh` | 事件字段可解析、transcript 存在、`tool_use` ≥10 | 不入队，静默退出 |
| 队列去重 | `worker.sh` | `mkdir` 原子锁，已有 worker 时退出 | 不重复启动 worker |
| 每日预算 | `worker.sh` | `MAX_JOBS_PER_DAY`（默认 3） | 任务保留在队列，次日继续 |
| 候选格式 | 候选落盘前 | frontmatter 必填字段、staging 路径限制 | 不写候选，保留任务 |
| 脱敏 | 候选落盘前 / 晋升前 | token、密码、内网地址等替换为 `<REDACTED>` | 阻断晋升，人工复核 |
| 原始记录检查 | 晋升前 | 长期记忆不得包含逐字稿、聊天记录、调试日志原文（R8） | 退回改写为“结论 + 出处” |
| provenance | 晋升前 | 每条资产带 `<!-- 来源: session <id>, <日期>, 理由: ... -->` | 补齐后写入 |
| 写入范围 | 晋升前 | 只写批准的目标路径；不直接改 `settings.json` | 拒绝写入，交人处理 |

## 人工卡点

| 卡点 | 谁批准 | 批准对象 | 未批准时 |
|---|---|---|---|
| 候选晋升 | 资产 owner / 提交人 | 候选表与目标位置 | 保留在 staging，不写正式资产 |
| hook / permissions 变更 | 用户 | 具体配置变更 | 只生成提案，不修改 `settings.json` |
| 公共级资产入库 | AI 平台团队 + 领域/组件 owner | 资产内容、owner、provenance | 不进入公共组件库 |
| 对外推送 / 发布 | 人 | 具体 commit / PR / 发布动作 | 不执行；只准备命令与说明（R3） |

## 质量门

一条候选进入正式资产库前，至少满足：

1. 跨 session 复现，或来源明确且经过验证；
2. 能命名失败模式或说明为什么值得沉淀；
3. 有明确 owner、适用边界与失效条件；
4. 与现有资产做过语义去重（新增 / 合并 / supersedes 有结论）；
5. 内容已脱敏，且不是原始记录的搬运。

## 回滚

- 误晋升：删除正式文件/条目，保留 git 历史；更新 staging INDEX 与蒸馏游标。
- 错误规则导致行为异常：删除或回退对应 rule/skill，记录原因；若是 hook，先移除 settings 条目再删脚本。
- 候选本身有误但已写入：保留 `supersedes` 链，新增修订候选，不做静默覆盖。
