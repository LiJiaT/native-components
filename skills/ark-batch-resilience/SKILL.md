# 方舟批量 LLM 流水线韧性运维

## 1. 区分「慢」与「僵死」

完成数连续 N 小时不动 + 日志 mtime 冻结 = 僵死；日志里 attempt 行仍在推进（s=c= 换新）= 健康——静默可能只是顺利 chunk 不打日志。

## 2. 褐化诊断三件套

1. **小探针**：curl 裸调端点，200/2-3s = 端点基础健康
2. **重负载探针**：带长正文对比——方舟典型褐化形态是小请求秒回、长思考请求挂死 600s
3. **lsof 查活跃连接**：⚠️ 连接走 IPv6 时 `:443` 显示为 `:https`，`grep 'https'` 才查得到，`grep ':443'` 恒为 0 会误判无连接。ESTABLISHED 连接端口号几分钟纹丝不动 = 服务端收请求不回话，定性为方舟侧容量问题：等恢复，勿瞎折腾

## 3. 修复优先级

- **调用级超时快速失败远优于看护杀轮**：译文/chunk 只在最后落盘，心跳杀轮丢掉全部在途进度，端点不稳时会无限磨
- 重思考 chunk 本身需 3-5 分钟，超时 180s 会误杀成死循环，放宽到 **300s**
- 心跳阈值必须大于长论文的健康静默期（收官期 15min→1h），否则永远凑不完一篇

## 4. 配额感知看护

- 429 报文解析 reset 时间：`grep 'AccountQuotaExceeded' | grep -oE 'reset at [0-9: ]+'`
- 窗口烧穿自动歇息等重置续跑，checkpoint 幂等（translated 状态落盘，重跑自动跳过）
- ⚠️ 配额烧穿时进程退出码仍是 0，会「骗」看护退出——看护必须校验 remaining 计数而非退出码
- 看护轮次上限耗尽会停摆（实测 40 轮），长跑任务要么设大要么无限循环

## 5. 防撞车

改并发/重启看护前 `pkill -9` 死透（**含 sleep 子进程**，ps 复核单链），否则旧看护没死透会拉起第二条链互踩状态文件（实测 3 秒内两条链并发写状态）。

## 6. 并发档位实证（2026-10）

| 档位 | 表现 |
|---|---|
| 16 路 | 不报 429 但方舟隐性排队，单请求延迟 ×3，实际吞吐 ~9-12 篇/小时，两天烧穿周配额（GLM/DeepSeek 共用账户配额，备用模型一起 429） |
| 4 路 | 窗口内最稳，~4-5 篇/小时 |

日吞吐天花板由配额总量决定，加并发只是「冲得更猛、停得更久」，想真提速只有升级套餐。僵死连接重启进程即愈（新进程新 socket），端点侧故障重启无效。
