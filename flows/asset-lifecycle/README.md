# 资产生命周期与退出流程（A02/A06/A08）

## 退役（withdraw）

由资产 owner 发起，K 记录保留历史，不做物理删除。

1. **影响清单**：列出引用该资产的项目、安装位置、组件版本与 owner；本机安装副本从安装清单/消费清单汇总。
2. **禁新用**：先把 `status` 置为 `withdrawn`，registry/INDEX/审批同步；新构建与安装必须拒绝。
3. **处理已装副本**：给出迁移或删除步骤，记录执行人与日期；`implementation.status` 不得在 record `withdrawn` 时仍为 `installed`。
4. **收尾证据**：保留退役决定、影响清单、迁移/删除结果与仍存在的风险。
5. **反馈**：若退役影响其他资产，登记关联关系并通知消费方。

## 替代、拆分、合并（A06）

只有在出现真实案例时才定义具体关系，不预先造平台。关系至少包含：

- 类型：`supersedes`、`split_from`、`merged_from`；
- 源/目标 `asset_id` 必须存在；
- 不允许自引用或环；
- 旧版本消费约定：哪些项目必须迁移、迁移验收证据、何时禁止新用；
- 关系写入 record/registry，并由 K 校验器和独立复核确认。

## 多消费者台账（A08）

单条 `installed` 日期不能表达多个使用方。出现第二个消费项目时，在消费项目侧维护 `asset-lock`（资产 ID、版本、owner、消费证据、更新/退出日期），K 侧按需汇总。没有第二个使用方前不建部署平台。
