# Orchestrator 快速上手指南

## 一句话理解

Orchestrator 是你 AI 工作流的"项目经理"：复杂任务它帮你拆、排、验、沉淀，简单任务它不打扰。

## 三种使用方式

### 方式 1：自动提示（推荐）

什么都不用做，直接说你的需求。`orchestrator-classify` hook 会**注入复杂度提示**，由主 agent / 你决定是否进入编排模式：
- 简单任务 → 不注入，直接执行，你感受不到它的存在
- 复杂任务 → 注入提示，主 agent 倾向于委派给 orchestrator

```
用户：帮我做一个完整的项目管理系统，前后端都要有
→ classifier 注入"复杂任务"提示 → 委派 orchestrator → 澄清 → 规划 → 分解 → 验收
```

### 方式 2：手动触发

明确要走工程化流程时，直接说：

- "用 orchestrator 处理这个任务"
- "按工程化流程来"
- "先规划再执行"

### 方式 3：作为 skill 调用

`/orchestrator` 或在 prompt 中提及编排/规划相关关键词。

## 典型使用场景

| 场景 | 为什么用 orchestrator |
|------|---------------------|
| 新项目开发 | 需求容易模糊，需要澄清和分解 |
| 多文件代码重构 | 需要规划影响范围和验证方案 |
| 研究调研类任务 | 输入输出不明确，容易跑偏 |
| 文档/方案撰写 | 需要结构化大纲和质量验收 |
| 跨工具流程编排 | 需要协调多个 skill/脚本 |

## 完整流程示例

以"做一个个人博客系统"为例：

### Step 0 · 分类
系统判断：多步骤、多产出物、需求不明确 → 复杂任务 → 进入编排

### Step 1 · 澄清（一次性问清）
```
## 需求澄清

基于我目前的理解：

### 🎯 目标
搭建一个个人博客系统，用于发布技术文章。
❓ 需要确认：主要用途是什么？技术笔记 / 知识分享 / 个人品牌？

### 🚧 约束
❓ 技术栈有偏好吗？推荐：Next.js + MDX（适合技术博客）

### 📥 输入
已有文章内容吗？还是从零开始？

### 📤 输出
需要部署吗？部署到哪里（Vercel / GitHub Pages / 自建）？

### 🧱 边界
评论系统、搜索、RSS 这些需要吗？
❓ 推荐 MVP 版只做核心功能（文章列表+详情+markdown）

### ✅ 验证标准
能正常访问、文章可正常渲染、响应式布局？
```

### Step 2 · 规划（确认后再动手）
```
## 执行计划

### 🎯 目标
搭建一个基于 Next.js 的个人技术博客 MVP

### 🚧 约束
- 技术栈：Next.js + Markdown；部署目标 Vercel
- 时间/资源：MVP 先不做评论与搜索

### 📥 输入
- 现有文章 Markdown 文件；站点标题/作者信息

### 📤 输出
- 可本地运行、可部署的站点仓库；构建与部署说明

### 🧱 边界
- 不做用户系统、评论、全文搜索；不改写作流程

### 🔀 任务分解
| # | 子任务 | 依赖 | 执行方 |
|---|--------|------|--------|
| 1 | 项目初始化 + 目录结构 | - | sub-agent |
| 2 | 文章列表页 + 详情页 | #1 | sub-agent |
| 3 | Markdown 渲染 + 代码高亮 | #2 | sub-agent |
| 4 | 样式 + 响应式布局 | #2 | sub-agent |
| 5 | 部署配置 + 验证 | #3, #4 | script + skill |

### ✅ 验收标准
1. 首页显示文章列表，点击进入详情
2. Markdown 文章正确渲染（标题/代码/列表/图片）
3. 代码块有语法高亮
4. 移动端适配正常
5. 可部署到 Vercel

### 👤 人工卡点
- 任务 1 完成后：确认目录结构
- 全部完成后：整体验收
```

### Step 3 · 分解分发
每个子任务生成任务包 → 并行/串行分发 → 子任务执行

### Step 4 · 验收
按验收清单逐项检查 → 自我批判 → 不通过回退 → 通过则交付

### Step 5 · 写回
- 踩过的坑 → 写入 memory
- 可复用的流程 → 考虑做成 skill
- 通用规则 → 写入 rules/

## 常见问题

**Q: 会不会太繁琐了，简单事情也搞复杂？**
A: 不会。Step 0 有分类器，简单任务直接执行，不会走完整流程。
你可以理解为"默认简单模式，复杂了会收到提示，由主 agent 决定是否进入编排"。

**Q: 流程执行到一半我想改需求怎么办？**
A: 随时说。编排智能体会判断是小调整还是大变更：
- 仅措辞/实现细节、且不影响验收标准 → 当前子任务内修正
- 影响目标、范围、输出或验收标准 → 必须回到规划阶段，重新确认并重新生成计划 hash（旧批准失效）
- 不确定是否影响验收 → 按大变更处理

**Q: 每个子任务都要等确认吗？**
A: 不是。只有"人工卡点"需要确认，其他子任务自动执行。
人工卡点默认只在高风险节点设置，不会每步都问。

**Q: 怎么跳过编排直接做？**
A: 用"简单做""快速"等明确表述，并避免同时出现多步骤/多产出信号。分类器是启发式：需要至少两个简单关键词且复杂信号不超过 2 个才判为简单；"不用规划"本身不在简单关键词表内。最终是否进入编排由主 agent 结合上下文决定。
